# SHA-256 Digest Chain (`sha256`)

[Back to the Stage 1 problem guide](README.md)

## Problem Statement

Compute a seeded chain of SHA-256 digests.
Each link hashes the complete 32-byte digest produced by the previous link.

The trusted function is `sha256Spec` in
[`Spec.lean`](../../evaluation/problems/sha256/Spec.lean).
Your implementation may use a different algorithm or representation, but it must equal
`sha256Spec` for every natural-number input.

Mathlib v4.33.1 has no dedicated SHA-256 implementation. Its general fixed-width
bit-vector API includes
[`BitVec.equivFin`](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Data/BitVec.html#BitVec.equivFin),
defined in the [fixed source](https://github.com/leanprover-community/mathlib4/blob/0df444a360eaa60ab8c11dca51a86af692955474/Mathlib/Data/BitVec.lean#L105-L110),
but that API does not specify SHA-256 padding, scheduling, compression, or this
seeded chain. The current target therefore remains the repository's core-Lean
`sha256Spec`.

The low 32 bits of the input select an initial digest.
Starting from the seed, the specification applies the 32-bit recurrence

```text
x' = (1664525 * x + 1013904223) mod 2^32
```

eight times. The eight successive values become the initial digest words `a` through `h`.

One chain step applies standard SHA-256 to those eight words as a 32-byte message.
The message is exactly the previous digest, not its decimal or hexadecimal text and not an
arbitrary string. Its single padded 512-bit block is:

```text
8 digest words, 0x80000000, five zero words, 0, 256
```

The compression starts from the standard SHA-256 initial state on every chain step and uses
the 64 standard round constants and 32-bit operations from FIPS 180-4.
At zero steps, no hash is performed and the seeded initial digest is returned.

See the [test configuration](../../evaluation/problems/sha256/config.json).

## Input

There is no standard-input stream.
The judge calls your Lean function with one parameter `n : Nat`.

The parameter uses the public packed encoding:

```text
n     = (steps << 32) | seed
steps = n >>> 32
seed  = n &&& 0xffffffff
```

All bits above the low 32 bits belong to `steps`.
The low coordinate is always reduced to 32 bits by the mask.
Hidden evaluation chooses two distinct 32-bit seeds at each published step count.

## Output

Return the final digest as a `Nat`.
Its eight 32-bit words are encoded in big-endian order:

```text
encode(a,b,c,d,e,f,g,h)
  = a*2^224 + b*2^192 + c*2^160 + d*2^128
  + e*2^96 + f*2^64 + g*2^32 + h.
```

Do not return a byte list, word tuple, string, or hash of the expected answer.

## Examples

```text
Input n:
4294967297

Output:
6974916886958575962243026017989799625410957637305596483321224775681667163855
```

Here `4294967297 = (1 << 32) | 1`, so the chain has one step and seed 1.
The seed recurrence produces the eight-word initial digest, SHA-256 hashes exactly those
32 bytes once, and the resulting eight words are encoded as the displayed big-endian `Nat`.

## Constraints and Scoring

The plan has three groups and six hidden cases:

| Group | Chain steps | Hidden cases | Target watchdog per repetition |
| --- | ---: | ---: | ---: |
| H1 | 4 | 2 | 30 s |
| H2 | 32 | 2 | 60 s |
| H3 | 512 | 2 | 120 s |

Memory: **4096 MiB (4 GiB)**. The [shared scoring rules](README.md#scoring)
and [resource limits](README.md#limits) apply.

## Submission Requirements

Submit one `Submission.lean` with these declarations inside `namespace Submission`:

```text
impl : Nat → Nat
impl_correct : ∀ n, impl n = sha256Spec n
```

`impl_correct` must prove equality for **all** `n`, not just the hidden step counts and seeds.

Use total, kernel-reducible core Lean code without Mathlib. The
[shared submission requirements](README.md#submission)
apply.

[problems/sha256/Submission.lean](../../problems/sha256/Submission.lean).
It retains the existing Window16 baseline: a fixed 16-field rolling message schedule.
The proof shows that the schedule equals `extendW`, the hash step equals

The separate [worked example](../../examples/sha256/Submission.lean) is a

Install `elan`, then run from the repository root:

## Notes

Possible approaches include packing words into larger `Nat` values, reducing masks and
projections, or fusing schedule and round computation.
Every alternative still needs a proof of the exact seed expansion, 32-bit operations,
single-block SHA-256 step, sequential chain, and final big-endian encoding.
Compiled speed does not predict kernel-replay cost; use the repository replay tooling when
comparing candidate designs.
