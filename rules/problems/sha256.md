# SHA-256 Digest Chain (`sha256`)

[Back to the Stage 1 problem guide](README.md)

## Problem Statement

Compute a seeded chain in which each step applies SHA-256 to the previous
32-byte digest. The trusted core-Lean function is `sha256Spec` in
[`Spec.lean`](../../evaluation/problems/sha256/Spec.lean).

## Input

The judge calls `impl n` with `n : Nat`, decoded as:

```text
n     = (steps << 32) | seed
steps = n >>> 32
seed  = n &&& 0xffffffff
```

All bits above the low 32 bits belong to `steps`. Starting from `seed`, apply

```text
x' = (1664525 * x + 1013904223) mod 2^32
```

eight times; the successive values form the initial digest words `a` through `h`.
Seed expansion happens once; subsequent steps hash only the preceding digest.
Zero steps returns this digest unchanged.

Each step hashes the previous digest's eight words as 32 bytes in big-endian
order, not text or an arbitrary message. Its single padded 512-bit block is:

```text
8 digest words, 0x80000000, five zero words, 0, 256
```

Every step starts from the standard SHA-256 initial state and uses the 64 round
constants and 32-bit operations from FIPS 180-4.

## Output

Return the final digest as a `Nat`, with its eight 32-bit words in big-endian order:

```text
encode(a,b,c,d,e,f,g,h)
  = a*2^224 + b*2^192 + c*2^160 + d*2^128
  + e*2^96 + f*2^64 + g*2^32 + h.
```

## Examples

```text
Input n:
4294967297

Output:
6974916886958575962243026017989799625410957637305596483321224775681667163855
```

Here `4294967297 = (1 << 32) | 1`: hash the seed-1 initial digest once, then
encode the result as a big-endian `Nat`.

## Constraints and Scoring

The [test plan](../../evaluation/problems/sha256/config.json) selects two distinct
32-bit seeds per group, for six hidden cases:

| Group | Chain steps | Hidden cases | Target watchdog per repetition |
| --- | ---: | ---: | ---: |
| H1 | 4 | 2 | 30 s |
| H2 | 32 | 2 | 60 s |
| H3 | 512 | 2 | 120 s |

Memory: **4096 MiB (4 GiB)**. The [shared scoring rules](README.md#scoring)
and [resource limits](README.md#limits) apply.

## Submission Requirements

Submit one `Submission.lean` with these declarations inside `namespace Submission`:

```text
impl : Nat → Nat
impl_correct : ∀ n, impl n = sha256Spec n
```

Prove equality for **every `n : Nat`**, including untested step counts and seeds.
This problem uses core Lean without Mathlib; the
[shared submission requirements](README.md#submission) apply.

## Starter Code and Local Testing

The [starter](../../problems/sha256/Submission.lean) and
[complete example](../../examples/sha256/Submission.lean) use a rolling 16-word
message schedule, proved equivalent to the specification.

Install `elan`, then run from the repository root:

```bash
cd problems/sha256
lake build
```

No separate setup is needed. Edit only `Submission.lean`. `lake build` checks
compilation and proofs, not official acceptance or performance.
See the [participant guide](../../problems/sha256/README.md) and
[optional kernel evaluation](../../evaluation/README.md).
