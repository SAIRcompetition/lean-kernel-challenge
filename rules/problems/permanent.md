# Seeded matrix permanent (`permanent`)

## Problem Statement

Compute the exact permanent of a deterministically generated square 0/1 matrix.
For a matrix `A` of dimension `d`, the permanent is:

```text
per(A) = sum over permutations σ of {0, ..., d - 1}
           of product over rows i of A[i, σ(i)]
```

Unlike the determinant, there are no signs. For a 0/1 matrix, this counts
perfect matchings: choose one `1` per row and use each column once. The locked
[Lean specification](../../evaluation/problems/permanent/Spec.lean) is the
proof target.

## Input

The argument `n : Nat` encodes a dimension and a 32-bit seed:

```text
n         = (dimension << 32) | seed
dimension = n >>> 32
seed      = n &&& 0xffffffff
```

Pack with `0 ≤ seed < 2^32`. This Lean function parameter is **not** standard
input and does not contain an arbitrary matrix; the matrix is
`genPermanentMatrix dimension seed`.

For `dimension ≥ 3`, row `i` has three distinct ones: column `i` and two
seeded off-diagonal columns. `permanentMix32` mixes the seed and row with fixed
salts. The choices are reduced modulo `dimension - 1` and `dimension - 2`,
skipping `i` and then both earlier choices. All other entries are zero; the spec
fixes the constants and skip functions.

Below dimension 3, the matrix is all ones. The diagonal guarantees a perfect
matching at every positive dimension. Seeds may generate the same matrix.

## Output

Return the exact `permanentSpecN n : Nat`, without modular reduction. The empty
matrix has permanent 1, so dimensions 0, 1, and 2 return 1, 1, and 2 for every
seed.

## Examples

| Input `n` | Dimension | Seed | Output |
| ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 1 |
| 4294967296 | 1 | 0 | 1 |
| 8589934592 | 2 | 0 | 2 |
| 12884901889 | 3 | 1 | 6 |
| 17179869186 | 4 | 2 | 8 |

At dimension 3, every row is full, so the result is `3! = 6`. The last table
entry uses the 4×4 matrix generated by seed 2. These are not hidden cases.

For comparison, `per([[1, 2], [3, 4]]) = 1 * 4 + 2 * 3 = 10`, but this is
**not** a competition instance because the generator produces only 0/1 entries.

## Constraints and Scoring

The [configuration](../../evaluation/problems/permanent/config.json) uses three
groups and **15 hidden cases**:

| Group | Dimension | Distinct hidden seeds | Target watchdog per repetition |
| --- | ---: | ---: | ---: |
| R1 | 6 | 5 | 30 s |
| R2 | 12 | 5 | 60 s |
| R3 | 16 | 5 | 120 s |

Each dimension gets five distinct 32-bit seeds, which need not produce distinct
matrices. A cohort uses one hidden plan for every submission.

Memory: **8192 MiB (8 GiB)**. The [shared scoring rules](README.md#scoring)
and [resource limits](README.md#limits) apply.

## Submission Requirements

Submit one `Submission.lean`, with these declarations in `namespace Submission`:

```text
impl : Nat → Nat
impl_correct : ∀ n, impl n = permanentSpecN n
```

The proof covers **every `Nat`**, including dimensions below 3, arbitrarily
large decoded dimensions, and every decoded seed—not only scored cases. This is
core Lean without Mathlib; the [shared requirements](README.md#submission) apply.
