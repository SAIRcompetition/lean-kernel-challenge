# Seeded matrix permanent (`permanent`)

## Problem Statement

Compute the exact permanent of a deterministically generated square 0/1 matrix.
For a matrix `A` of dimension `d`, the permanent is:

```text
per(A) = sum over permutations σ of {0, ..., d - 1}
           of product over rows i of A[i, σ(i)]
```

Unlike the determinant, there is no sign attached to a permutation. For a 0/1
matrix, the result counts ways to choose one `1` from each row, using each
column exactly once. Equivalently, it counts perfect matchings of the matrix's
bipartite graph. The locked Lean [specification](../../evaluation/problems/permanent/Spec.lean)
is the submission's proof target.

Mathlib v4.33.1 has the standard permutation-sum definition
[`Matrix.permanent`](https://leanprover-community.github.io/mathlib4_docs/Mathlib/LinearAlgebra/Matrix/Permanent.html#Matrix.permanent),
defined in the [fixed source](https://github.com/leanprover-community/mathlib4/blob/0df444a360eaa60ab8c11dca51a86af692955474/Mathlib/LinearAlgebra/Matrix/Permanent.lean#L27-L32).
It is a possible future specification, not the current target. No all-input
theorem connects the repository's list matrix and mask traversal to
`Matrix.permanent`; `permanentSpecN` therefore remains the binding core-Lean
specification and must not be described as already Mathlib-certified.

## Input

The argument `n : Nat` encodes a dimension and a 32-bit seed:

```text
n         = (dimension << 32) | seed
dimension = n >>> 32
seed      = n &&& 0xffffffff
```

Use `0 ≤ seed < 2^32` when packing. This is a Lean function parameter, **not**
standard input. The input does not contain an arbitrary matrix: use the
matrix produced by `genPermanentMatrix dimension seed`.

At dimension at least 3, each row `i` has exactly three distinct ones: column
`i` and two seeded off-diagonal columns. All other entries are zero.
`permanentMix32` mixes the seed and row index with two fixed salts. The first
choice is reduced modulo `dimension - 1` and skips `i`; the second is reduced
modulo `dimension - 2` and skips both previous choices. The spec contains the
exact constants and skip functions.

At dimensions below 3, the generator uses the all-ones square matrix.
The diagonal guarantees a perfect matching whenever the dimension is positive.
Different seeds may generate the same matrix.

## Output

Return `permanentSpecN n : Nat`, the exact permanent, with no modular reduction.
The empty matrix has permanent 1. Consequently dimensions 0, 1, and 2 have
outputs 1, 1, and 2, respectively, for every seed.

## Examples

| Input `n` | Dimension | Seed | Output |
| ---: | ---: | ---: | ---: |
| 0 | 0 | 0 | 1 |
| 4294967296 | 1 | 0 | 1 |
| 8589934592 | 2 | 0 | 2 |
| 12884901889 | 3 | 1 | 6 |
| 17179869186 | 4 | 2 | 8 |

At dimension 3, the three ones fill every row, so the result is `3! = 6`.
The final example is the particular 4×4 matrix generated by seed 2.
These identities are kernel-checkable with `rfl` against the spec, not a list
of official hidden cases.

For comparison, the mathematical permanent of `[[1, 2], [3, 4]]` is
`1 * 4 + 2 * 3 = 10`. That toy matrix is **not** a seeded competition instance:
the generator only produces 0/1 entries.

## Constraints and Scoring

The current [configuration](../../evaluation/problems/permanent/config.json) uses three
groups and **15 hidden cases**:

| Group | Dimension | Distinct hidden seeds | Target watchdog per repetition |
| --- | ---: | ---: | ---: |
| R1 | 6 | 5 | 30 s |
| R2 | 12 | 5 | 60 s |
| R3 | 16 | 5 | 120 s |

The packed sampler fixes the dimension and derives five distinct 32-bit seeds
per group. Distinct seeds need not produce distinct matrices. All submissions
in the same cohort receive the same hidden plan.

Memory: **8192 MiB (8 GiB)**. The [shared scoring rules](README.md#scoring)
and [resource limits](README.md#limits) apply.

## Submission Requirements

Submit one `Submission.lean`, with these declarations in `namespace Submission`:

```text
impl : Nat → Nat
impl_correct : ∀ n, impl n = permanentSpecN n
```

The proof covers **every `Nat`**, not just the scored dimensions or sampled seeds.
It must handle dimensions below 3 and arbitrarily large decoded dimensions.
Any algorithm satisfying the
[shared requirements](README.md#submission) is permitted;
this problem uses core Lean without Mathlib. The locked
[challenge](../../evaluation/problems/permanent/Challenge.lean) and
[solution bridge](../../evaluation/problems/permanent/Solution.lean) fix the interface.

## Notes

The baseline traverses column choices depth first, recording occupied columns in
a bit mask. It skips zero entries and used columns without materializing every
permutation. Subset dynamic programming or a sparse row representation may avoid
repeated work, but any optimization must preserve the generator and exact count
for all inputs and be measured in the kernel.
